# ระบบแจ้งปัญหาและติดตาม Ticket

## รายละเอียดโครงการ
ระบบสำหรับแจ้งปัญหาด้าน IT และติดตามสถานะการดำเนินงาน
ตั้งแต่ก# ระบบแจ้งและติดตามปัญหา (Mini Helpdesk / Issue Tracking System)

ระบบเว็บสำหรับแจ้งและติดตามปัญหาภายในองค์กรขนาดเล็ก ช่วยให้ผู้ใช้งานสามารถแจ้งปัญหา ตรวจสอบสถานะ และติดตาม Ticket ได้อย่างเป็นระบบ ขณะที่เจ้าหน้าที่และผู้ดูแลระบบสามารถจัดการ Ticket มอบหมายงาน และบันทึกผลการแก้ไขได้

## ภาพรวมของโครงการ

ระบบ Mini Helpdesk พัฒนาขึ้นสำหรับจัดการปัญหาและคำร้องของผู้ใช้งาน เช่น ปัญหาคอมพิวเตอร์ โปรแกรม ระบบเครือข่าย เครื่องพิมพ์ และอุปกรณ์ภายในห้องเรียนหรือสำนักงาน

ระบบแบ่งการใช้งานออกเป็น 3 มุมมองหลัก ได้แก่

* **User View** — สำหรับผู้ใช้งานทั่วไป
* **Staff View** — สำหรับเจ้าหน้าที่
* **Admin View** — สำหรับผู้ดูแลระบบ

ระบบจัดเก็บข้อมูลด้วย `LocalStorage` ของ Web Browser จึงสามารถทดลองใช้งานได้โดยไม่จำเป็นต้องติดตั้ง Backend หรือ Database

---

## ฟังก์ชันของระบบ

### User

ผู้ใช้งานสามารถ

* สร้าง Ticket แจ้งปัญหา
* ระบุหัวข้อและรายละเอียดของปัญหา
* เลือกประเภทปัญหา
* ระบุสถานที่
* กำหนดระดับความสำคัญ
* ดูรายการ Ticket ของตนเอง
* ดูรายละเอียด Ticket
* แก้ไข Ticket ที่อยู่ในสถานะ `Open`
* ยกเลิก Ticket ที่อยู่ในสถานะ `Open`
* ตรวจสอบสถานะของ Ticket
* ค้นหา Ticket

### Staff

เจ้าหน้าที่สามารถ

* ดูรายการ Ticket ที่ได้รับมอบหมาย
* ดูรายละเอียดปัญหา
* ตรวจสอบข้อมูล Ticket
* เปลี่ยนสถานะ Ticket
* เพิ่มหมายเหตุการแก้ไข (Resolution Note)

### Admin

ผู้ดูแลระบบสามารถ

* ดู Ticket ทั้งหมด
* ดูรายละเอียด Ticket
* ค้นหา Ticket
* กรอง Ticket ตามประเภท สถานะ ระดับความสำคัญ และผู้รับผิดชอบ
* มอบหมาย Ticket ให้เจ้าหน้าที่
* เปลี่ยนสถานะ Ticket
* เพิ่มหมายเหตุการแก้ไข
* แก้ไขข้อมูล Ticket
* ลบ Ticket
* จัดการประเภทปัญหา (Issue Type)
* ดู Dashboard และข้อมูลสรุปของ Ticket

---

## สถานะของ Ticket

ระบบใช้สถานะสำหรับติดตามการดำเนินงาน ได้แก่

| สถานะ         | รายละเอียด                       |
| ------------- | -------------------------------- |
| `Open`        | Ticket ใหม่ที่ยังไม่ได้ดำเนินการ |
| `In Progress` | Ticket ที่กำลังดำเนินการแก้ไข    |
| `Resolved`    | Ticket ที่ดำเนินการแก้ไขแล้ว     |
| `Cancelled`   | Ticket ที่ถูกยกเลิก              |

---

## ระดับความสำคัญ

Ticket สามารถกำหนดระดับความสำคัญได้ 4 ระดับ

* `Low`
* `Medium`
* `High`
* `Urgent`

---

## ประเภทปัญหา

ระบบมีประเภทปัญหาหลัก ได้แก่

* Computer Hardware
* Software/Application
* Network/Internet
* Printer/Scanner
* Classroom/Lab Room
* Account/Login
* Other

ผู้ดูแลระบบสามารถเพิ่มหรือลบประเภทปัญหาได้จากหน้า **Issue Type Management**

---

## หมายเลข Ticket

ระบบจะสร้างหมายเลข Ticket ให้อัตโนมัติเมื่อผู้ใช้งานสร้าง Ticket ใหม่ เช่น

```text
JJK-0001
JJK-0002
JJK-0003
```

หมายเลข Ticket จะเพิ่มขึ้นตามลำดับของ Ticket ที่สร้างขึ้น

## เทคโนโลยีที่ใช้

* **HTML5** — โครงสร้างหน้าเว็บ
* **CSS3** — การออกแบบและจัดรูปแบบหน้าเว็บ
* **JavaScript** — การทำงานและจัดการข้อมูลของระบบ
* **LocalStorage** — จัดเก็บข้อมูล Ticket และ Issue Type ภายใน Web Browser
* **Git / GitHub** — จัดการและเผยแพร่ Source Code

ระบบในเวอร์ชันปัจจุบันเป็น Frontend Web Application และยังไม่มีการเชื่อมต่อกับ Backend หรือ Database ภายนอก

## การจัดเก็บข้อมูล

ระบบใช้ `LocalStorage` ในการจัดเก็บข้อมูลภายใน Web Browser เช่น

* ข้อมูล Ticket
* หมายเลข Ticket
* ประเภทปัญหา (Issue Type)

ข้อมูลจะถูกจัดเก็บไว้ใน Browser ของเครื่องที่ใช้งาน

> หากล้างข้อมูลเว็บไซต์หรือ Browser Storage ข้อมูล Ticket ที่จัดเก็บไว้ในเครื่องนั้นอาจถูกลบ

## การค้นหาและกรองข้อมูล

* Issue Type
* Status
* Priority
* Assigned Staff

## Dashboard

หน้า Dashboard ใช้สำหรับแสดงภาพรวมของ Ticket ในระบบ เช่น

* จำนวน Ticket ทั้งหมด
* จำนวน Ticket สถานะ `Open`
* จำนวน Ticket สถานะ `In Progress`
* จำนวน Ticket สถานะ `Resolved`
* จำนวน Ticket สถานะ `Cancelled`
* สรุป Ticket ตามประเภทปัญหา
* สรุป Ticket ตามระดับความสำคัญ

## การพัฒนา

โครงการนี้จัดทำขึ้นเพื่อศึกษาและฝึกปฏิบัติด้านการพัฒนา Web Application โดยเน้นการออกแบบระบบจัดการ Ticket การทำ CRUD การจัดการสถานะ การมอบหมายงาน การค้นหาและกรองข้อมูล รวมถึงการแสดงข้อมูลสรุปผ่าน Dashboard

ในระหว่างการพัฒนา มีการใช้เครื่องมือ AI เป็นผู้ช่วยในการอธิบายโค้ด ตรวจสอบข้อผิดพลาด แนะนำแนวทางการพัฒนา และช่วยปรับปรุงโครงสร้างบางส่วนของระบบ โดยผู้พัฒนาเป็นผู้ตรวจสอบและทดสอบการทำงานของระบบด้วยตนเอง

## ข้อจำกัดของระบบ

ระบบเวอร์ชันปัจจุบันมีข้อจำกัดดังนี้

* ใช้ LocalStorage แทน Backend และ Database
* ยังไม่มีระบบ Login และ Authentication จริง
* ข้อมูลไม่ได้ถูกแชร์ระหว่างเครื่องหรือผู้ใช้งานหลายคน
* ยังไม่มีระบบแจ้งเตือนผ่าน Email หรือ LINE
* ยังไม่รองรับการแนบไฟล์
* การแบ่ง User, Staff และ Admin เป็นการจำลองผ่านหน้าใช้งานของระบบ
